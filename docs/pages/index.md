## 概要

ルートページ（`/`）は、アプリケーションの入口です。Discord OAuth認証コードをクエリパラメータで受け取った場合、自動的に `/auth/callback` にリダイレクトします。認証後のデフォルトナビゲーション先は `/roles`（ロール管理ページ）です。

## 主要要件

- OAuth認証コードを処理してログインフロー開始
- 認可後、ユーザーを指定のページにリダイレクト
- クエリパラメータ `code` と `next` から遷移先を決定
- セキュリティ：`next` パラメータは `/` で始まるパスのみ許可

## 非機能要件

- ページ遷移時の UI フラッシュなし（SSR レンダリング）
- リダイレクト処理は サーバーサイドで実行

## 必要項目・操作

### クエリパラメータ
| パラメータ | 型 | 必須 | 説明 |
|-----------|-----|------|------|
| `code` | string | × | Discord OAuth認証コード。存在時に `/auth/callback` へリダイレクト |
| `next` | string | × | 認証後の遷移先。デフォルト `/roles` |

## 操作

1. **認証コードあり時**
   - `code` パラメータを検出 → `/auth/callback?code=...&next=...` へリダイレクト
   - `next` が `/` で始まるパスなら採用、そうでなければ `/roles`

2. **認証コードなし時**
   - トップページの静的HTML をレンダリング（テンプレート状態）
   - Next.js デフォルトテンプレート表示

## 仕様API

利用API：なし（SSR レンダリングのみ）

## 関連DB

なし

## 備考

- 現在の実装では、認証なし時のUIはNext.jsのデフォルトテンプレート（"To get started..." メッセージ）
- 今後、サークル情報やニュースを表示するランディングページへ変更予定の可能性あり

## 実装メモ

- `redirect()` は Next.js 13+ のサーバーコンポーネント機能
- `searchParams` は `Promise<...>` の場合があり、`await Promise.resolve()` で解決
- セキュリティ：`next` パラメータのバリデーション重要（オープンリダイレクト対策）
