# ロール管理 一般メンバー表示仕様 (`MemberSelfView`)

本ドキュメントは、一般メンバー（`app_role` が `member` / `sub_user` / `obog` のいずれか）としてログインした際に `/roles` で表示される個人用ロール管理ビュー（`MemberSelfView`）の画面要件・操作仕様です。

---

## 1. 概要
一般メンバーはサーバー全体のロール構成編集は行えず、**自分自身に対するセルフロール（関心分野、学年、サークル内チーム等）の付与・解除** と、**セルフ付与できるカテゴリ（ゲーム・スキル等）への権限なしロールの新規作成** のみ行えます。
UI上で変更をトグル選択し、「変更を保存してDiscordへ反映」ボタンを押すことで、DBおよびDiscordサーバーと自動同期されます。
作成したロールはサーバー全体で共有され、他のメンバーもセルフ付与できます。ロールの編集・削除、カテゴリの作成・編集、Discord 権限の変更は管理者のみ行えます。

---

## 2. 画面構成要素

1. **ユーザープロフィールヘッダー**:
   - Discord アバター、表示名、現在の権限（`member` / `sub_user` / `obog`）を表示。
   - ログアウトリンク（`/auth/signout?callbackUrl=/`）。
2. **ステータス・フィードバックバナー**:
   - 保存中（`saving`）、保存完了（`saved`）、エラー（`error`）の視覚的通知。
   - 未保存の変更がある場合のインジケータ。
3. **ロールカテゴリ一覧（アコーディオン）**:
   - カテゴリ単位で展開／折りたたみが可能。
   - カテゴリ内のロール一覧と、現在の自身への付与状態（チェックマーク／トグルボタン）。
   - セルフ付与できるカテゴリ（`is_restricted: false`）のヘッダー右側には「＋」ボタンを表示し、ロール作成モーダルを開く（ヘッダーの開閉は行わない）。管理者専用カテゴリには従来どおりロール数と「管理者専用」を表示する。
   - セルフ付与できるカテゴリは、ロールが 0 件でも表示する（「ロールはまだありません」と表示し、「＋」から作成できる）。管理者専用カテゴリはロールが 0 件なら表示しない。
4. **ロール作成モーダル（`NewRoleModal` の member モード）**:
   - 管理者の新規作成モーダルと同じ入力 UI のうち、ロール名（1〜100 文字）とカラーのみ入力できる。カテゴリは「＋」を押したカテゴリに固定し、権限設定タブは表示しない（`permissions = 0`）。Hoist はオフ、Mentionable はオンで固定。
   - 「作成」で `POST /api/roles/self-create` を呼び、完了まで「作成中...」と表示してボタンを無効化する。失敗時はモーダル内に HTTP ステータスに応じた固定文言を表示する。
5. **保存・同期アクションバー**:
   - 「変更を保存してDiscordへ反映」ボタン。
   - 変更がある場合のみ活性化。

---

## 3. 操作フローと制約

### 操作フロー
1. **ロールの選択・解除**:
   - 自身に付与したいロールのチェックボックス／トグルをクリック（ローカル state で保持）。
   - 「未保存の変更があります」と画面に明示。
2. **保存と同期の実行**:
   - 「変更を保存してDiscordへ反映」をクリック。
   - 変更前後の差分（`roles_to_add`, `roles_to_remove`）を抽出し、一括更新 API（`/api/roles/self-batch`）を 1 回呼び出しで実行。
   - 処理完了後、Discord サーバー側のロールおよび DB 割当がアトミックに即座に反映され、成功メッセージを表示。
3. **ロールの作成**:
   - セルフ付与できるカテゴリの「＋」をクリックし、ロール名とカラーを入力して「作成」をクリック。
   - 未確定の付与・解除がある場合は、先に「変更を確定」するよう案内し、モーダルを開かない（作成後に一覧を読み直すため）。
   - Backend が Discord へのロール作成・マニフェストへの保存・自分への付与までを 1 回のリクエストで行う。
   - 成功すると「ロール「…」を作成して付与しました」と表示し、`router.refresh()` でマニフェストを読み直して一覧に反映する（ページのリロードは行わない）。
   - 付与だけに失敗した場合（`assigned: false`）は、ロールは作成済みである旨と「＋ 付与」での付与を案内するエラーバナーを表示する（自動では消えない）。

| HTTP ステータス | 表示文言 |
|---|---|
| 400 | Discord ID が特定できません。Discordアカウントで再ログインしてください。 |
| 401 | ログインの有効期限が切れました。再度ログインしてください。 |
| 403 | このカテゴリにはロールを作成できません。 |
| 409 | 同じ名前のロールがすでにあります。既存のロールを付与するか、別の名前にしてください。 |
| 422 | ロール名またはカラーの形式が正しくありません。 |
| 429 | ロールの作成回数が上限に達しました。しばらく時間をおいてから再度お試しください。 |
| 502 | Discordへのロール作成に失敗しました。時間をおいて再度お試しください。 |
| その他 | ロールの作成に失敗しました。時間をおいて再度お試しください。 |

### 安全制約（Hierarchy Protection）
- **Bot 上位ロールの保護**: Discord Bot 自身の持つロール階層より上位のロール、および `is_restricted`（管理者限定カテゴリ）のロールは一般メンバーからは操作・選択できません（UI上で無効化表示）。
- **権限付きロールの保護**: `permissions` が `0` 以外（Discord 権限付き）のロールは「変更不可」と表示し、操作できません。
- **カテゴリ未設定ロールの保護**: カテゴリ未設定のロールは「ロール一覧」に閲覧のみで表示され、操作できません。
- **チャンネル権限上書きの保護**: チャンネル上書きで権限を許可されているロールは、新たにセルフ付与できません。既に持っているロールの解除は可能です。
- 上記の制約は UI だけでなく Backend（`POST /api/v1/roles/self-batch`）でも検証されます。チャンネル上書き一覧を取得できない場合は、セルフ付与を中止します。
- **ロール作成の制約**: 作成先はセルフ付与できるカテゴリに限り、`permissions` は Backend で `0` に固定します。カテゴリ・同名ロール（大文字・小文字と前後の空白は無視）・入力形式・回数制限（10 分間に 5 回）は Backend（`POST /api/v1/roles/self-create`）で検証します。
- **注意**: `permissions = 0` はサーバー全体の権限を持たないことを意味しますが、チャンネルごとの権限上書き（permission overwrites）は別設定です。チャンネル権限を付与する必要があるロールは `is_restricted` カテゴリに配置してください。

## 4. 仕様API（Route Handlers 経由）

- **ロール割当一覧取得**: `GET /api/roles/members`
- **セルフロール一括更新（バッチ処理）**: `POST /api/roles/self-batch`
  ```json
  {
    "roles_to_add": ["123456789012345678"],
    "roles_to_remove": ["234567890123456789"]
  }
  ```
  **レスポンス (200 OK)**:
  ```json
  {
    "ok": true,
    "added": ["123456789012345678"],
    "removed": ["234567890123456789"]
  }
  ```
- **ロール作成**: `POST /api/roles/self-create`（Backend `POST /api/v1/roles/self-create`。仕様は [`docs/api/v1/roles.md`](../../api/v1/roles.md) を参照）
  ```json
  {
    "name": "Minecraft",
    "color": "#3498DB",
    "category_id": "cat-game"
  }
  ```
